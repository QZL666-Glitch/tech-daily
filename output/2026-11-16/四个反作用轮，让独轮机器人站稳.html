四个反作用轮，让独轮机器人站稳

来源：GitHub · 2026-11-16

引言

独轮机器人天生不稳定：只有一个接地点，前后左右都容易倒。常见的做法是装一个又大又重的反作用轮，靠它加速旋转产生的反力矩把车身"掰"回来。但单个轮子只能对付一个方向的倾斜，侧向怎么办？GitHub 上一个名为 reaction-wheel-monowheel 的开源项目给出了另一种思路：用四个反作用轮，按 45° 角布置，配合数字孪生和硬件在环测试，把"站稳"这件事从仿真一路做到实机。对做机器人控制、嵌入式开发的人来说，这是一个把机械设计、控制理论和嵌入式固件串起来的完整案例。

四个轮子，为什么是 45°

反作用轮 stabilisation 的原理不复杂：轮子加速转，车身就受到反方向力矩。白话讲，就像你坐在转椅上猛地转动手里的小风扇，椅子会往反方向拧一下。单个轮子只能产生绕自身轴线的力矩，所以传统独轮车只能控制俯仰（前后倒），侧向倾倒无能为力。

这个项目的做法是布置四个反作用轮，两两成对、以 45° 夹角安装。这样每个轮子的力矩可以分解到俯仰和横滚两个方向上，组合起来就能同时抑制前后和左右的倾斜。素材中提到的"4 wheels at 45°"正是这一布局的核心。项目还专门做了尺寸选型（sizing），也就是根据车体质量和惯量反推轮子需要多大、多快——这一步决定了整套系统有没有足够的控制 authority（控制能力）。

从 Python 生成 CAD 到两轴测试台

机械部分有一个值得注意的细节：CAD 模型最初由 Python 脚本生成，之后在 SolidWorks 中重建。用代码生成结构模型的好处是参数可调、便于迭代，改一个尺寸不用从头画图。

更关键的是那个"两轴测试台"（two-axis test rig）。在把控制算法装进真车之前，先做一个能绕两个轴自由倾斜的台架，把反作用轮组固定在上面测试。这样可以在受控条件下观察俯仰和横滚两个通道的响应，而不必担心机器人一开机就摔。这是典型的"先台架、后整机"的工程路径。

数字孪生：Simscape 与 Webots 双线并行

项目建了两套数字孪生。一套在 MATLAB 的 Simscape 里，偏重物理建模和控制律验证；另一套在 Webots 里，偏重三维场景下的机器人行为仿真。两套模型并行，相当于用不同工具交叉验证同一套控制策略。

控制上采用了基于观测器（observer-based control）的方法。白话解释：传感器未必能直接测到所有状态量，观测器就是用一个数学模型去"推算"那些测不到的量，再拿推算结果参与控制。相比单纯的 PID，这类方法在状态不完全可测时更有优势——素材的标签里同时出现了 pid-control 和 observer-based control，说明项目可能在不同层级上混用了这些手段。

ESP32 固件与硬件在环

最终的控制代码跑在 ESP32 上，用 C++ 编写，基于 FreeRTOS 和 PlatformIO 开发。ESP32 是常见的双核 Wi-Fi/蓝牙微控制器，用它做实时控制需要处理好任务调度——FreeRTOS 在这里负责把控制循环、传感器读取、通信拆成不同优先级的任务。

项目还搭了硬件在环（HIL）台架：把真实的 ESP32 控制器接进仿真回路，让固件去控制虚拟的被控对象。这样能在不摔坏实机的前提下，测试固件在极限工况下的表现。整个项目还带有 MBSE（基于模型的系统工程）和 Capella 的标签，说明作者在系统架构层面也做了建模，而不只是写代码。

小结

这个项目的价值不在于某个单点技术有多新，而在于它展示了一条完整的开发链路：用代码生成结构、用台架验证机构、用双仿真环境验证控制、用 HIL 验证固件，最后才落到实机。四个 45° 布置的反作用轮解决了单轮无法侧向稳定的老问题，而观测器控制、Simscape/Webots 双孪生、ESP32 + FreeRTOS 固件这些环节，恰好覆盖了机电一体化项目从建模到落地的典型工序。对想入门自平衡机器人或反作用轮控制的开发者来说，这是一个结构清晰、层次完整的参考样本。

小白常见问题

Q1：为什么独轮机器人天生站不稳？

因为它只有一个接地点，支撑面近似一个点，重心稍有偏移就会绕接地点倾倒，前后左右都没有被动恢复力。必须靠主动控制（比如反作用轮）不断产生纠正力矩，才能维持平衡。这也是它比两轮自平衡车更难的原因。

Q2：反作用轮和普通飞轮有什么区别？

反作用轮本质就是一个可正反加速的转子，靠角动量变化产生的反力矩作用于车身。它不靠“陀螺定轴”稳定，而是靠“加速时反拧车身”。所以控制的核心是精确控制轮的角加速度，而不是让它一直高速空转。

Q3：一个轮子不够，为什么不用两个，而要四个？

单轮只能产生绕自身轴线的力矩，只能管一个倾斜方向。两个轮子若轴线平行，仍只覆盖一个通道；若正交布置可覆盖两轴，但力矩分配和冗余不如四轮灵活。四轮 45° 布置让每个轮子的力矩都能分解到俯仰和横滚，组合自由度更高（具体选型理由文中未说明，此处为通用原理解释）。

Q4：45° 布置到底妙在哪里？

每个轮子的力矩轴与俯仰轴、横滚轴都成 45°，所以它同时贡献两个方向的力矩分量。四个轮子成对配合，就能独立或联合地产生俯仰、横滚力矩。相当于用四个“斜着推”的力，合成出前后和左右两个方向的纠正力矩。

Q5：什么是“尺寸选型（sizing）”，为什么关键？

就是根据车体质量和转动惯量，反推轮子需要多大、多重、能转多快，才能产生足够的纠正力矩。选小了“掰不动”车身，选大了又重又费电。它决定了整套系统有没有足够的控制 authority，是设计的第一步硬约束。

Q6：数字孪生为什么要做两套（Simscape 和 Webots）？

Simscape 偏物理建模与控制律验证，Webots 偏三维场景下的整机行为仿真。两套模型并行，相当于用不同工具交叉验证同一套控制策略，降低“在一种仿真里调通、换环境就失效”的风险。这是工程上常见的冗余验证思路。

Q7：观测器控制和 PID 是什么关系？

PID 直接用误差反馈，简单但依赖可测信号；观测器用数学模型推算测不到的状态量，再把推算值送进控制器。两者不是替代关系，常配合使用：观测器负责“补状态”，PID 或状态反馈负责“出控制量”。文中标签同时出现两者，具体分工文中未说明。

Q8：ESP32 做实时控制靠谱吗？FreeRTOS 起什么作用？

ESP32 是双核 Wi-Fi/蓝牙 MCU，主频和资源足以跑中小型控制循环，但需要合理调度。FreeRTOS 把控制循环、传感器读取、通信拆成不同优先级的任务，保证控制任务按时执行。是否满足具体控制频率要求，以官方最新说明和实测为准。

Q9：硬件在环（HIL）测试有什么好处？

把真实 ESP32 接进仿真回路，让固件控制虚拟被控对象。这样可以在不摔坏实机的前提下，测试极限工况、参数摄动和故障场景，提前暴露固件里的调度、溢出、时序问题。它是“台架之后、实机之前”的关键一道关。
